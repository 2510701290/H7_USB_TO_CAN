# H7_USB_TO_CAN 30 节课程大纲

## 课程定位

本课程围绕当前项目展开，目标是从“能编译和运行”逐步达到“能解释、能测量、能修改、能设计”。最终能够独立分析 Linux 主机经 USB、STM32H723 和 FDCAN 到达电机驱动器的完整控制链路。

建议每节课 60～120 分钟，其中约一半时间用于实验。所有实验结果记录到 `Tutorial/` 目录中，不只记录结论，也记录命令、日志、数据和未解决问题。

## 总体路线

```text
项目认知
  → C/C++ 与构建基础
  → Zephyr 内核
  → DeviceTree / Kconfig / STM32H7 硬件
  → CAN / FDCAN
  → USB 基础与 Zephyr USB
  → gs_usb / Linux SocketCAN
  → 实时性、可靠性和安全
  → 综合改造项目
```

## 模块一：建立项目全局认知（第 1～5 课）

### 第 1 课：项目目标与系统架构

**目标**：理解项目为什么不需要传统意义上的下位机，以及各设备的职责。

**核心内容**：

- USB-to-CAN 网桥的定位。
- Linux 主机、STM32、CAN 总线和电机驱动器的关系。
- “主机直控”与“下位机闭环控制”的优缺点。
- 命令链路和反馈链路。

**实践任务**：

- 画出一帧命令和一帧回复的端到端时序图。
- 标出主机、USB、STM32 线程、中断、消息队列和 CAN 总线。

**完成标准**：能用自己的话解释一条 `cansend` 命令如何到达电机。

### 第 2 课：仓库结构与代码导航

**目标**：建立“文件—模块—功能”的对应关系。

**核心内容**：

- `src/`、`inc/`、`boards/`、`docs/`、`userpy/`、`Tutorial/` 的职责。
- `main.cpp`、`Basic_USB`、`Basic_CAN`、`M_S_Control`、线程文件的关系。
- 头文件、实现文件和全局对象。

**实践任务**：

- 为每个源文件写一句功能说明。
- 找出项目的入口函数、所有线程和所有 CAN 回调。

**完成标准**：不查资料也能快速找到 USB 初始化、CAN 启停和 RTT 命令处理的位置。

### 第 3 课：C/C++ 嵌入式代码基础

**目标**：补齐阅读本项目所需的 C/C++ 知识。

**核心内容**：

- 指针、数组、结构体、枚举和函数指针。
- `const`、`static`、`extern`、`volatile` 的常见用途。
- C++ 类、构造函数、成员初始化和删除拷贝构造。
- 弱符号 `__attribute__((weak))` 的用途。

**实践任务**：

- 解释 `_M_S_Control` 构造函数保存的每一个指针。
- 找出 `CAN_RX_Cplt` 的函数指针类型和实际回调。

**完成标准**：能安全修改一个回调或配置数组而不破坏链接关系。

### 第 4 课：Git、West 和构建流程

**目标**：理解从源码到固件的完整过程。

**核心内容**：

- Git 工作区、提交和差异查看。
- `west.yml`、manifest 和 Zephyr 依赖。
- `west build`、增量构建和 pristine 构建。
- CMake 如何收集源文件并生成固件。

**实践任务**：

- 完成一次全新构建。
- 修改日志文本、重新编译并确认烧录结果。
- 比较增量构建和 `--pristine` 构建。

**完成标准**：能够独立判断问题来自源码、配置还是构建缓存。

### 第 5 课：烧录、RTT 和基础调试

**目标**：建立稳定的运行观察和调试流程。

**核心内容**：

- pyOCD、J-Link、Ozone 和 RTT 的关系。
- 日志等级、延迟日志和 RTT 缓冲区。
- `assert`、错误码和启动失败定位。
- USB 设备重新枚举的必要性。

**实践任务**：

- 使用 RTT 观察启动日志。
- 制造一个可恢复的初始化错误，记录错误链路。
- 使用 `USB_RESET.py` 验证重新枚举。

**阶段检查点**：能编译、烧录、查看日志，并画出项目启动顺序。

## 模块二：Zephyr 软件基础（第 6～10 课）

**目标**：理解 Zephyr 如何启动应用和系统服务。

- 线程栈、线程名和线程分析器。
- 中断上下文与线程上下文的区别。

**实践任务**：

- 统计 RTT、CAN 回环和 USB 相关线程的运行关系。
- 调整一个线程优先级，记录 CAN 延迟变化。

### 第 8 课：消息队列、信号量和原子变量

- `k_sem_take/give` 与临界区。
- `atomic_inc/clear` 和并发统计。

**实践任务**：

- 追踪 `basic_can2_q` 从接收回调到处理线程的完整生命周期。

### 第 9 课：日志、断言和运行时观测

**目标**：用可观测性替代猜测。

**核心内容**：

- 日志模块、日志等级和 deferred logging。
- RTT 后端与缓存区满时的丢日志行为。
- `CONFIG_ASSERT`、错误码和错误传播。

**实践任务**：

- 给 CAN 启停和 USB 状态切换增加结构化日志。
- 用线程分析器记录一次负载较高时的栈使用率。

### 第 10 课：并发问题与数据所有权

**目标**：建立嵌入式并发设计意识。

**核心内容**：

- 优先级反转、死锁和竞态条件。

**实践任务**：

- 画出所有 CAN 消息队列和 USB 缓冲区的所有权图。
- 找出 `k_msgq_purge()` 可能导致的丢帧场景。

## 模块三：硬件描述与 STM32H7（第 11～14 课）

### 第 11 课：Kconfig 和 `prj.conf`

**目标**：掌握编译期功能和资源配置。

**核心内容**：

- Kconfig 的布尔、数值和依赖关系。

- 如何查找某个 `CONFIG_` 的来源和用途。

**实践任务**：

- 解释 `CONFIG_USBD_GS_USB_MAX_CHANNELS`、`CONFIG_UDC_BUF_COUNT` 和日志缓冲区。
- 改动一个配置并比较构建产物大小。

### 第 12 课：DeviceTree 语法与设备绑定

**目标**：能从 DTS 读取硬件连接关系。

**核心内容**：

- `DEVICE_DT_GET`、`DT_NODELABEL` 和设备驱动绑定。
- board 文件和 SoC `.dtsi` 的覆盖关系。
- 生成的 devicetree 与 C 代码的关系。

**实践任务**：

- 找出 `gs_usb0`、`can_loopback0`、`fdcan2` 和 `zephyr_udc0`。
- 解释 `can_channels[]` 如何映射到硬件通道。

### 第 13 课：时钟、PLL 和 USB 48 MHz

**目标**：理解主频、外设时钟和通信时序。

**核心内容**：

- H7 的时钟树、PLL、总线分频和 APB 时钟。

**实践任务**：

- 根据 DTS 计算 SYSCLK、FDCAN 时钟和 USB 时钟。

### 第 14 课：内存、Cache、DMA 和调试区域

**目标**：理解 H7 内存布局与通信缓冲区。

**核心内容**：

- Flash、AXI SRAM、DTCM、ITCM、D2/D3 SRAM。
- Cortex-M7 D-Cache 一致性。
- `RTT_NOCACHE` 区域的作用。
- 栈、堆、静态对象和 USB/CAN 缓冲区。

**实践任务**：

- 估算工程中线程栈、日志和 USB 缓冲区的内存占用。

**阶段检查点**：能从 `prj.conf` 和 DTS 推断主要 RAM、时钟和外设资源。

## 模块四：CAN 和 FDCAN（第 15～20 课）

### 第 15 课：CAN 总线协议基础

**目标**：建立 CAN 的位级和帧级模型。

**核心内容**：

- 标准帧、扩展帧、ID 仲裁和 ACK。
- SOF、控制域、数据域、CRC、EOF。
- 位填充和错误检测。
- 总线负载和传输时间。

**实践任务**：

- 手算一个 8 字节经典 CAN 帧的近似占线时间。
- 用示波器、逻辑分析仪或 CAN 工具观察一帧报文。

### 第 16 课：CAN FD 和位时序

**目标**：理解 CAN FD 与经典 CAN 的差异。

**核心内容**：

- FDF、BRS、ESI 和更长数据段。
- Nominal Bitrate 与 Data Bitrate。
- Sample Point、BRP、TSEG 和 SJW。
- 1 Mbps 仲裁段与 5 Mbps 数据段的配置。

**实践任务**：

- 对比经典 CAN 和 CAN FD 报文的总线时间。
- 验证主机和 STM32 的位时序配置是否一致。

### 第 17 课：Zephyr CAN API 与虚拟回环

**目标**：用最小实验掌握 Zephyr CAN API。

**核心内容**：

- `can_set_mode()`、`can_set_bitrate()`、`can_start()`。
- `can_send()` 和接收回调。
- `can-loopback` 设备的用途。
- 非阻塞、超时和发送完成回调。

**实践任务**：

- 使用 `CAN_loopback_thread` 发送递增数据。
- 在 `CAN_LB_RX_Cplt()` 中接收并打印数据。
- 检查每次 API 调用的返回值。

### 第 18 课：真实 FDCAN、过滤器和 Message RAM

**目标**：掌握 `fdcan2` 的实际接收路径。

**核心内容**：

- FDCAN 引脚和外设时钟。
- Bosch Message RAM 分区。
- 标准过滤器、扩展过滤器和 RX FIFO。
- `CAN_Clear_All_Filters()` 的作用。

**实践任务**：

- 配置全通滤波器，再改为只接收指定 ID。
- 统计 RX FIFO 溢出和丢帧。

### 第 19 课：CAN 状态、错误和 Bus-Off

**目标**：能诊断 CAN 不工作的原因。

**核心内容**：

- Error Active、Error Passive、Warning 和 Bus-Off。
- ACK、位错误、CRC、格式和填充错误。
- `CONFIG_CAN_STATS` 和错误计数。
- 状态回调、自动恢复和安全停机。

**实践任务**：

- 制造波特率不匹配、断线和终端电阻错误。
- 记录内核 `ip -d -s link`、Zephyr 日志和统计值。

### 第 20 课：RM 电机协议与应用层帧设计

**目标**：理解 CAN 原始帧如何表达电机命令。

**核心内容**：

- `Send_RM()` 的 ID、DLC 和大端数据编码。
- 有符号 16 位电机目标值的范围和缩放。
- 命令帧、反馈帧、ID 规划和版本兼容。
- “只保存 8 字节数据”对应用的限制。

**实践任务**：

- 设计包含 ID、DLC、Flags、Payload 和时间戳的 `CanMessage`。
- 为发送和接收增加序号、计数器和错误统计。

## 模块五：USB、gs_usb 和 Linux SocketCAN（第 21～25 课）

### 第 21 课：USB 基础与全速总线

**目标**：理解项目所使用的 USB 传输模型。

**核心内容**：

- 主机独占调度和设备应答。
- 控制、批量、中断和同步传输。

- Full-Speed 12 Mbps、1 ms SOF 和 64 字节最大包。

**实践任务**：

- 计算一个经典 CAN 帧或 CAN FD 帧通过 USB 批量端点的大致成本。
- 解释为什么批量传输有可靠性但没有固定时延保证。

### 第 22 课：USB 枚举、描述符和端点

**目标**：理解主机如何识别设备并启用端点。

**核心内容**：

- Device、Configuration、Interface、Endpoint、String 和 BOS 描述符。
- GET_DESCRIPTOR、SET_ADDRESS、SET_CONFIGURATION。
- EP0 控制传输的三阶段。
- 本项目的 VID/PID、Full-Speed 配置和端点兼容模式。

**实践任务**：

- 使用 `lsusb -v` 对照 `Basic_USB.h` 的定义。
- 找出 USB 重新枚举失败时可能卡住的初始化步骤。

### 第 23 课：Zephyr USB Device Stack

**目标**：掌握本项目的 USB 初始化过程。

**核心内容**：

- `usbd_add_descriptor()`。
- `usbd_add_configuration()`。
- `usbd_register_class()`。
- `usbd_init()` 与 `usbd_enable()`。
- UDC 中断线程、USB 协议栈线程和类线程。

**实践任务**：

- 为每个 USB 初始化步骤记录返回值和失败日志。
- 观察设备复位、配置完成和端点可用的时间顺序。

### 第 24 课：gs_usb 协议和通道控制

**目标**：理解 Linux `gs_usb` 驱动如何控制 STM32 CAN 通道。

**核心内容**：

- `HOST_FORMAT`、`DEVICE_CONFIG`。
- `BT_CONST`、`BITTIMING` 和 `DATA_BITTIMING`。
- `MODE(RESET/START)`。
- `GET_STATE`、错误状态和设备事件回调。
- `gs_usb_register()` 与 CAN 驱动的连接。

**实践任务**：

- 从 `ip link set canN up` 追踪到 `can_start()`。
- 记录 `USB_CHANNEL_STARTED`、RX/TX activity 和 error 事件。

### 第 25 课：Linux SocketCAN、python-can 和 USB 抓包

**目标**：掌握主机侧测试和协议观察方法。

**核心内容**：

- SocketCAN 网络设备模型。
- `ip link`、`candump`、`cansend` 和 `python-can`。
- `lsusb`、usbmon、Wireshark。
- USB 控制请求与 CAN 数据帧的对应关系。

**实践任务**：

- 完成从 USB 枚举、建立 `can0/can1` 到发送 CAN 帧的完整抓包。
- 验证主机波特率、STM32 波特率和电机总线参数一致。

**阶段检查点**：能解释“USB 设备已枚举但 CAN 通道无法启动”的至少三种原因。

## 模块六：实时性、可靠性与安全（第 26～30 课）

### 第 26 课：端到端延迟和抖动测量

**目标**：建立可重复的性能测试方法。

**核心内容**：

- 延迟、吞吐量、周期、抖动和尾部延迟。
- 平均值、中位数、p95、p99、p99.9 和最大值。
- 主机、USB、Zephyr、CAN 和电机响应的分段测量。
- 外部 CAN 分析仪与内部时间戳的差异。

**实践任务**：

- 复现 `docs/CAN_ANALYSIS*.md` 中的测试。
- 给命令和反馈增加序号，计算配对延迟。

### 第 27 课：吞吐量、背压和丢帧分析

**目标**：知道系统在高负载下哪里会先失效。

**核心内容**：

- USB Full-Speed 的带宽上限。
- USB 缓冲池、CAN FIFO、消息队列和线程处理能力。
- `K_NO_WAIT`、队列满和丢帧策略。
- “只保留最新值”和“每帧可靠传递”的区别。

**实践任务**：

- 逐步提高发送频率，记录丢帧点和 CPU/栈使用率。
- 为每个环节增加入队、出队、丢弃和错误计数器。

### 第 28 课：故障注入与恢复设计

**目标**：建立系统化的故障诊断能力。

**核心内容**：

- USB 断开、主机崩溃、STM32 重启。
- CAN 断线、Bus-Off、设备未启动和发送队列满。
- 通道状态机和错误事件。
- 自动恢复、人工恢复和恢复失败的边界。

**实践任务**：

- 为每种故障写出“检测—记录—隔离—恢复—验证”流程。
- 检查 `C_M_TO_S()` 与 `C_S_TO_M()` 的状态转换和错误路径。

### 第 29 课：主机直控的安全设计

**目标**：把通信系统变成可控、可停、可验证的控制系统。

**核心内容**：

- 心跳与命令新鲜度。
- 指令超时、最大速度/电流限制和斜坡限制。
- USB/CAN 断开后的安全停止。
- 电机使能、急停和硬件安全链路。
- 失效模式与影响分析（FMEA）的基本方法。

**实践任务**：

- 设计一个“主机超过指定时间没有新命令，电机自动进入安全状态”的方案。
- 明确该功能由主机、STM32 还是电机驱动器实现，以及每层的兜底关系。

### 第 30 课：综合项目与最终答辩

**目标**：把整个课程的知识用于一次可验证的工程改进。

**建议项目**：实现一个完整的 CAN 通信监控与安全控制版本。

至少包含：

1. 完整 `CanMessage` 元数据，而不只是 8 字节 payload。
2. 收发、丢帧、队列满、Bus-Off 和 USB 状态统计。
3. 命令序号或时间戳。
4. 通信超时后的安全动作。
5. RTT 或 USB 可查询的运行状态。
6. 一份延迟和压力测试报告。
7. 一份故障注入和恢复报告。
8. 一张最终端到端时序图。

**最终答辩问题**：

- 一条主机命令经过哪些线程、中断和缓冲区？
- 哪些环节会造成延迟和丢帧？
- CAN Bus-Off 后系统如何处理？
- 主机崩溃或 USB 拔出时，电机如何安全停止？
- 当前方案的最大控制频率和主要限制是什么？
